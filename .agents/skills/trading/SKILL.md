# TradingAgents → Robinhood MCP Agent Skill

## Purpose
Automate the full pipeline from market discovery to deterministic trade execution, with human-in-the-loop approval.

## STRICT ADHERENCE RULES (Non-Negotiable)
To prevent "shortcut reasoning," the agent MUST adhere to these boundaries:

1. **Discovery vs. Decision**: 
   - **MCP Tools** (`get_financials`, `get_equity_technical_indicators`, etc.) are for **DISCOVERY ONLY**. Use them to find candidates and narrow the universe.
   - **The CLI** (`cli.main`) is for **DECISIONS**. No trade may be proposed without a corresponding `complete_report.md` generated by the CLI.
2. **No Vacuum Recommendations**: 
   - Never recommend a "Buy" or "Sell" based solely on market data. Every recommendation MUST be audited against the user's actual portfolio (`rboin__get_portfolio`) and the `risk_profile.json`.
3. **Quantitative Sizing**: 
   - "Strong Buy" is not a proposal. A proposal MUST include: **Ticker, Entry Price, Stop Loss, and Exact Share Quantity** based on the `risk_profile.json` caps.

## 🛠 Technical Execution Standards
To avoid timeouts and environment errors, the agent MUST use these patterns:

- **Python Path**: Always use the absolute path to the venv: `/home/spak/TradingAgents/.venv/bin/python`
- **Execution Pattern (Long-Running CLI)**:
  Since `cli.main` can take several minutes, do NOT run it synchronously. Use the **Background & Poll** pattern:
  1. **Launch**: `nohup /home/spak/TradingAgents/.venv/bin/python -m cli.main --ticker <TICKER> --date $(date +%Y-%m-%d) --analysts market,news --save --no-show > /home/spak/.tradingagents/logs/cli_last_run.log 2>&1 &`
  2. **Poll**: Check for the existence of the report file in `/home/spak/.tradingagents/logs/reports/<TICKER_...>/complete_report.md`.
  3. **Wait**: If the file is not yet present, perform a small unrelated task (e.g., check portfolio) or simply wait 30 seconds before checking again.
  4. **Verify**: Once the file exists, read it to proceed to the Synthesis phase.

## 📓 Journaling Standards
To prevent "Thesis Amnesia" across sessions, the agent MUST maintain a persistent record in `/home/spak/TradingAgents/trading_journal/`.

- **Recall**: Before analyzing any ticker already in the portfolio, the agent MUST read `<TICKER>.md` to understand the original reason for the trade.
- **Entry Record**: Upon executing a BUY, create/update `<TICKER>.md` with:
  - Date, Entry Price, Quantity.
  - **Original Thesis**: The core catalyst from the `complete_report.md`.
  - **Exit Plan**: The Stop Loss and the specific conditions that would break the thesis.
- **Update Record**: When a position is audited but held, **APPEND** a timestamped note using `insert_line` at the end of the file explaining why the thesis remains intact. Do not attempt to replace existing text.
- **Exit Record**: Upon executing a SELL/TRIM, record:
  - Date, Exit Price, Realized PnL.
  - **Post-Mortem**: Did the thesis hold? Why was the exit triggered?

## The "Make Money" Workflow (Orchestration)
When the user says "make money" or "find opportunities", the agent MUST follow this exact sequence:

1. **Discovery (The Eyes)**:
   - Audit current portfolio for candidates.
   - Use `rboin__run_scan` or `rboin__create_scan` to identify 3-5 new high-probability candidates.
   - Use MCP tools to filter for basic value/growth metrics (e.g., PEG, RSI).

2. **Deep Analysis (The Brain)**:
   - Recall original thesis from `trading_journal/` for existing holdings.
   - For each candidate, launch the analysis CLI using the **Background & Poll** pattern described above.
   - Read the resulting `complete_report.md`. **Do not substitute this with direct MCP calls.**

3. **Synthesis & Ranking**:
   - Compare the reports. Rank candidates by `confidence_score` and `Rating` (Buy > Overweight > Hold > Underweight > Sell).

4. **Portfolio & Risk Audit (The Filter)**:
   - Call `rboin__get_portfolio` and `rboin__get_equity_positions`.
   - Read `/home/spak/TradingAgents/risk_profile.json`.
   - Calculate the exact quantity that fits within `max_position_pct` and `max_position_usd`.

5. **The Verification Checklist**:
   - Before presenting the proposal, the agent MUST print:
     - [ ] Portfolio audited & original theses recalled
     - [ ] `cli.main` executed for candidates (via background poll)
     - [ ] `complete_report.md` synthesized
     - [ ] Portfolio audit performed
     - [ ] `risk_profile.json` validated

6. **The Proposal**:
   - Present the structured proposal:
     - **Ticker**: [SYMBOL]
     - **Thesis**: [Brief summary from report + comparison to original thesis]
     - **Action**: [Buy/Sell/Trim] at [Entry/Exit Price] with Stop at [Stop Loss]
     - **Sizing**: [Quantity] shares (~$[Amount])
     - **Risk Check**: [PASSED/FAILED] based on `risk_profile.json`

7. **Execution & Journaling (The Hands)**:
   - **Await explicit user approval**.
   - If approved: `rboin__review_equity_order` $\rightarrow$ `rboin__place_equity_order`.
   - **Immediately update the `trading_journal/` for the ticker.**

## Inputs & Constraints
- **Date**: Always use current date (`date +%Y-%m-%d`).
- **Analysts**: Default to `market,news`.
- **Risk Profile**: Strictly adhere to `risk_profile.json`.
- **Safety**: Never execute `place_equity_order` without a prior `review_equity_order` and user confirmation.
